whole-view aesthetic — variants

Three directions for the overall app chrome (topbar, dock area, panel borders, bottombar, ambient background). Panel contents are not changing. Each mockup also demonstrates the rename from --honey-* to --accent-* so the personalize panel can later swap the palette in one place.

All three mockups use --c-accent-rgb: 240, 179, 90 — the current honey. Swap that one line and the whole UI re-themes (cool blue, monochrome, sepia, whatever). That's what color-agnostic naming buys you.

what gets renamed (regardless of pick)

  • src/honey-glass.css → src/glass.css
  • --honey-XX → --accent-XX (alpha ladder, ~40 tokens)
  • --honey-deep-XX → --accent-deep-XX
  • --honey, --honey-bright → --accent-deep, --accent
  • --hg-honey, --hg-honey-deep, --hg-honey-pale → --hg-accent, etc. (or drop the hg- prefix entirely)
  • CSS classes containing "honey" in component files
  • Reference: ~22 files touch these names. Mechanical sed-style refactor.

what stays

  • RGB triplet palette in tokens.css stays exactly where it is (top of file, well-documented) — that's the personalize panel's hook.
  • Role-named tokens (--ink, --muted, --line, --panel) keep their names — they're already color-agnostic.
  • Surface ladder (--surface-N-NN) already color-agnostic.
